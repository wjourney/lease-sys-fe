# 租赁管理系统角色权限与菜单梳理

整理日期：2026 年 10 月 14 日。范围：本地前后端代码。下文保留调整前的权限基线和已确认的菜单方案；实际改动见“已实施调整”。

系统共有五个角色。超级管理员管理全局；内部运营管理租赁业务与账号；内部财务负责收付款和财务处理；销售公司管理员查看本公司业务并维护公司资料；销售员工查看本人业务。权限需要同时区分菜单入口、页面访问、业务操作和数据范围。

## 已实施调整

- 内部菜单统一使用“销售公司”和“系统设置”，网站品牌配置页面改为“网站设置”；资料标题统一为“文件与资料”。
- 公司管理员菜单为“可租项目、本公司资料、本公司订单、佣金统计、佣金明细”；销售员工菜单为“可租项目、所属公司、我的订单、佣金统计、佣金明细”。销售项目页说明展示可租和在租单位。
- 运营新增“账单查询”入口；超级管理员和内部财务新增财务分组下的“发票管理”；财务只读账号入口改为“账号查询”。
- 登记收款表单提示核对到账、直接入账以及每张账单须一次付清。
- 运营可查看后端已按订单管理权限返回的订单佣金，隐藏无权限的独立佣金详情入口；没有财务权限时，订单押金栏目改为“押金情况”。
- 销售端保留订单内收款查看，隐藏不可访问的独立账单及发票页面链接；没有佣金读取能力时隐藏销售端佣金菜单并拦截对应页面。
- 增加统一路由权限检查，禁止无权限页面挂载和发起数据请求；销售端原有跳转规则保留，其他拒绝访问统一显示无权限页。
- 网站设置加载失败时保留错误信息及重试入口，成功提示统一使用“网站设置已保存”。

公司管理员成员管理、销售员工成员可见范围、后端角色能力及数据范围保持原规则。本次没有增加后端授权。

## 角色职责与数据范围

| 当前角色名称 | 角色标识 | 可见数据范围 | 主要职责与限制 |
| --- | --- | --- | --- |
| 超级管理员 | SUPER_ADMIN | 全部业务数据 | 全局业务、财务、账号和配置管理；业务状态及引用关系仍限制操作 |
| 内部运营 | OPERATIONS | 有读取权限的全部业务数据 | 项目、单位、订单、销售公司、账号和配置管理；可登记收款；不能管理超级管理员和内部财务账号 |
| 内部财务 | FINANCE | 全部业务资源可读取 | 管理账单、支出、佣金、发票、银行账户和资料；项目、单位、订单、公司与账号只读；不能修改网站配置 |
| 销售公司管理员 | SALES_COMPANY_ADMIN | 本公司订单、佣金及关联账单；本公司成员与公司资料 | 公司基本资料可编辑；公司图片和 Logo 可维护；不能新增公司、删除公司、修改服务期限或管理成员账号 |
| 销售员工 | SALES | 本人归属订单、本人佣金及订单关联账单；本公司资料与成员 | 业务只读，不能创建订单、登记收款或管理成员 |

销售端的额外数据规则：

- 项目只显示启用的项目，单位只显示启用项目下的启用单位，并非只显示本公司成交过的项目。
- 销售公司管理员可查看本公司订单；销售员工还必须是订单归属销售人员。本人创建记录不等于本人归属订单。
- 两类销售角色都可读取本公司成员，销售员工并非只能看到自己的成员信息。
- 资料仅显示允许范围内且标记为共享的资料，包括项目、单位、订单、账单、发票、本公司和本人关联资料。
- 项目出租方资料及额外信息不返回销售端；订单的单位与销售快照不返回销售端。
- 项目未开启“销售可查看准确租金”时，销售端不返回单位参考月租及单位类型参考租金。
- 公司管理员的统计覆盖本公司佣金，可按员工筛选；销售员工统计仅覆盖本人佣金。销售端统计当前固定使用港币，按约定结付日期统计，作废佣金不计入汇总。

补充说明：

| 通用文件资料管理 | 允许 | 允许 | 允许 | 只读，公司图片例外 | 只读 |

关键边界：

- 当前登记收款会直接生成已确认收款并入账，不是“运营提交、财务审核”的流程；要求一次付清账单剩余金额，不支持单张账单部分付款。确认、驳回主要用于历史待确认记录。
- 运营编辑订单时可维护订单关联佣金；这与进入佣金模块或登记佣金付款是不同权限。
- 公司管理员可编辑公司名称、中英文名称、联系人、电话、邮箱、地址、服务区域、注册信息及收款银行资料；服务起止日期、部门和职位配置不在其允许修改字段中。
- 公司管理员没有通用 `materials` 写权限，但后端为本公司图片与 Logo 的新增、删除以及排序保留专用权限；不能由此推导其能维护订单附件或任意资料。
- 不能停用自己的账号；至少保留一位启用的超级管理员。删除及停用还受业务引用和服务端校验约束。

采用按角色表达任务的命名：内部角色使用“管理”，销售端使用“我的”或“本公司”明确范围；同一业务名称在菜单、面包屑、页面标题和表单中保持一致。

| 位置 | 当前文案 | 建议文案 | 原因 |

| 销售项目入口 | 项目 | 可租项目 | 销售端展示启用项目和单位；可在页内说明已租单位也可查看 |

建议菜单结构：

| 角色 | 一级入口与子菜单 |
| --- | --- |
| 超级管理员 | 项目管理、销售公司、订单管理、账号管理、财务管理（账单管理、押金管理、佣金管理、支出管理、发票管理、资金流水、财务统计）、系统设置（银行账户、网站设置） |
| 内部运营 | 项目管理、销售公司、订单管理、账号管理、账单查询、系统设置（银行账户、网站设置） |
| 内部财务 | 项目管理、销售公司、订单管理、账号查询、财务管理（账单管理、押金管理、佣金管理、支出管理、发票管理、资金流水、财务统计）、系统设置（银行账户） |
| 销售公司管理员 | 可租项目、本公司资料、本公司订单、佣金统计、佣金明细 |
| 销售员工 | 可租项目、所属公司、我的订单、佣金统计、佣金明细 |

此结构建议给内部运营增加现有账单页面入口，给管理员与财务增加发票页面入口；文件与资料继续从业务详情进入。新增菜单本身不扩大后端数据或操作权限。

## 调整前规则与差异处理

| 事项 | 当前行为 | 建议处理 |
| --- | --- | --- |
| 运营收款职责 | 运营没有财务菜单，但能直接打开账单并登记收款，登记立即入账 | 确认运营负责收款；若保留，补“账单查询”入口，并明确直接入账提示 |
| 公司管理员成员管理 | 可查看本公司成员，不能新增、编辑、停用、重置密码 | 暂按现状；如业务希望管理成员，需要单独设计账号授权，不能只开放菜单 |
| 销售员工成员可见范围 | 后端允许读取本公司成员，前端从公司详情查看成员 | 确认员工是否需要查看所有成员，以及电话等信息的可见字段 |
| 销售端发票入口 | 收款详情按发票读取能力显示发票链接，但销售端 `/invoices` 路由会跳回项目 | 若需要查看，做订单内发票预览或专用只读入口；若不需要，隐藏该链接并收紧对应能力 |
| 运营订单佣金栏目 | 服务端订单详情返回关联佣金，但前端按通用佣金读取权限显示无权限 | 确认运营是否需要核对订单佣金；随后统一栏目权限与服务端返回规则 |
| 发票与资料导航 | 页面存在，但无独立侧栏菜单；发票可从收款详情进入 | 发票增加财务子菜单；资料保留业务内入口，统一标题 |
| 通用路由权限 | 部分路由由页面自身或 API 拒绝访问，通用详情并未统一做读取权限入口检查 | 后续统一路由权限与无权限页；后端继续作为最终授权边界 |
| 销售端佣金菜单 | 两个菜单按销售角色直接追加，没有再校验佣金读取能力 | 当前五角色配置下正常；未来动态授权时应与能力配置一致 |
| 销售端命名 | 只读页面仍叫订单管理；佣金统计叫财务统计 | 按上一节统一名称、标题、面包屑及简繁体文案 |
